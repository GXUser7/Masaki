# Masaki и Chrome: обзор возможностей и исправлений

Проверка от 10 ноября 2026 года. Основа — `main`, `924293d`, версия 0.7.0;
`git pull --ff-only` подтвердил совпадение с `origin/main`; на момент начала проверки последним выпуском был v0.7.0.
Исправления этого обзора включены в версию 0.7.2. Публикация 0.7.1 не состоялась из-за
отключённого GitHub runner macos-14; release workflow переведён на macos-15.

Обзор охватывает устройство `src/main`, preload, состояние и команды renderer, настройки,
меню, вкладки, поиск, менеджеры паролей и ключей, разрешения, расширения, профили,
импорт, синхронизацию, загрузки, обновления, медиа и YouCloud. Углублённые проверки
выполнены для перечисленных ниже изменений. Это обзор реализации и совместимости,
а не утверждение, что каждый сайт, устройство и сценарий браузера проверены.

## Исправлено

| Сценарий | Причина | Изменение |
|---|---|---|
| После выбора логина/пароля клик по «Войти» перехватывался новым списком паролей | Фокус снова попадал в поле пароля после завершения заполнения; асинхронные ответы могли заново показать меню | Заполненные поля запоминаются до редактирования. Программный возврат фокуса не открывает меню; явный клик позволяет сменить аккаунт. Устаревшие запросы отменяются, клик вне поля закрывает список сразу. `preload/guest.ts` |
| Google считал браузер небезопасным при входе из панели | Замена user agent в `did-start-navigation` была слишком поздней для первого документа новой вкладки. Заголовки уже сообщали Firefox, а первый скрипт мог видеть Chrome | Сессионный preload согласует `navigator` с заголовками до скриптов Google. Убраны поздняя смена UA и перезагрузка окна входа; обычные страницы сохраняют Chrome и Client Hints. `preload/popup.ts`, `main/index.ts` |
| Ссылка Telegram не открывала приложение | Для прикладных URI не было обработки навигации, `window.open` и разрешения `openExternal` | Обработка обычной ссылки, HTTP-редиректа, новой вкладки/окна и запроса Chromium. Подтверждение в интерфейсе, передача Windows только после ответа; отмена/уход со страницы снимает запрос, пустая вкладка не создаётся. `main/externalProtocols.ts`, `Permissions.tsx` |
| В поле уже стоит фокус, а passkey не появляется | Сайт начинал conditional-запрос позже, чем preload запрашивал список ключей | Начало и завершение запроса обновляют список у уже сфокусированного поля; отмена убирает предложения. `main/passkeys.ts`, `preload/guest.ts` |
| Ключ Masaki сообщал о входе с телефона | `getTransports()` возвращал `hybrid`, хотя собственного hybrid-провайдера нет | Созданный ключ сообщает только `internal`; существующие сохранённые ключи не меняются |
| Нельзя бросить текст/картинку в док или панель | Перенос картинки принимала только уже открытая палитра | Панель и док принимают текст, URI, файл изображения и HTML-перенос картинки со страницы; открывается заполненная палитра. Результат идёт в новую вкладку. Перестановка своих вкладок и плиток помечена отдельно. `lib/searchDrop.ts`, `main/searchImage.ts` |
| Панель сначала серая, затем прозрачная | `.app.animating .side` на 520 мс подменял фон на `--glass-pop` и выключал размытие | Убрана подмена поверхности во время анимации. Сохранена FLIP-анимация страницы через `transform`, без покадрового изменения её ширины. `styles/app.css` |

Вход Google проверен на подставных ServiceLogin/AddSession и OAuth-окне: первый скрипт
видит согласованный `navigator`, ответ `window.opener` доходит до сайта, форма не перезагружается,
после ухода с Google обычный сайт видит Chrome. Живая проверка входа Google не выполнена:
автоматическая проверка разрешений отклонила запуск, конкретная причина не сообщена.
Пароли и аккаунты пользователя в проверках не использовались. Наличие формы входа само по себе
тоже не подтвердило бы успешную авторизацию.

## Чего не хватает относительно Chrome

«Нет» ниже означает отсутствие реализации в Masaki. «Частично» — есть отдельный путь,
но он не покрывает все сценарии. Отсутствие проверки конкретного устройства отдельно отмечено.

| Возможность | Состояние Masaki и где это видно | Приоритет |
|---|---|---|
| Пароли и passkey во встроенных iframe | Собственный мост принимает только главный фрейм (`fromTab` в `main/index.ts`). WebAuthn iframe остаётся системному провайдеру, а ключи Masaki ему недоступны | Высокий |
| Вход passkey с телефона через QR/Bluetooth | Собственного hybrid-пути нет; менеджер больше не сообщает его как транспорт. Кнопка «Ключ безопасности…» передаёт запрос нативному WebAuthn, доступность устройств зависит от ОС и здесь не проверялась | Высокий |
| Тихое создание passkey после входа паролем | `mediation: conditional` у create явно отклоняется, `conditionalCreate: false` (`preload/passkey-page.ts`) | Средний |
| Согласование ключей после удаления на сайте | Методы Signal API не связаны с `passkeys.json`. Нативный Signal API не обновляет собственное хранилище Masaki; возможны устаревшие записи после удаления ключа на сервере | Высокий |
| Расширения WebAuthn PRF / largeBlob | Мост create передаёт только `credProps`, get не передаёт расширения. Сценарии вывода ключа шифрования и больших данных ключа не реализованы | Средний |
| Повторная проверка владельца сейфа | Закрытые ключи зашифрованы DPAPI, а флаг UV ставится после подтверждения в интерфейсе. Отдельного PIN/Windows Hello перед каждой операцией собственного менеджера нет (`flags`, `answer` в `main/passkeys.ts`) | Высокий для защиты сейфа |
| Автозаполнение адресов, телефонов, платёжных карт | В preload распознаются логин и пароль; хранилищ контактов/карт и UI их выбора нет | Средний |
| Генерация и проверка паролей | Есть хранение, редактирование, импорт и синхронизация. Генератора, проверки утечек/повторов и экспорта пользовательского CSV нет (`passwords.ts`, `PasswordsPage.tsx`) | Средний |
| «Войти через Google» с FedCM | FedCM выключен, используется OAuth-окно с `window.opener`. Полноценного браузерного окна FedCM нет | Высокий, если сайт не предлагает popup-путь |
| Надёжный Google OAuth для собственной синхронизации | Есть PKCE, loopback callback и вариант системного браузера (`sync.signIn(external)`); по умолчанию вход открывается внутри Masaki. Совместимость UA не является гарантией принятия встроенного браузера Google | Высокий |
| Демонстрация экрана в видеозвонках | Нет `setDisplayMediaRequestHandler`, выбора экрана/окна и обработки `display-capture` в списке разрешений; общий обработчик неизвестное право отклоняет (`setupBrowsingSession`) | Высокий |
| WebUSB / WebHID / Web Serial / Web Bluetooth | Нет собственных обработчиков выбора USB/HID/serial/Bluetooth-устройств и интерфейса выбора; подключения реального оборудования не проверялись | Высокий для сервисов устройств |
| HTTP/прокси-аутентификация | Нет обработчика Electron `login` и диалога логина/пароля для HTTP Basic/Digest или прокси. Формы на сайтах — отдельный работающий путь | Высокий для корпоративных ресурсов |
| Установка сайтов как приложений (PWA) | Нет менеджера установленных веб-приложений, установочного потока и регистрации их окон/ярлыков; наличие service worker в Chromium этого не заменяет | Средний |
| Регистрация сайтом веб-обработчика протокола | Передача прикладного URI Windows добавлена. Отдельного управления `navigator.registerProtocolHandler` и назначенными веб-сервисами нет | Средний |
| Перевод страницы | В настройках, меню и действиях нет браузерного перевода; переводчик как отдельный сайт/расширение — другой сценарий | Средний |
| Папки закладок | `chromeBookmarks` раскрывает дерево в плоский список; модель `Shortcut` не содержит папок | Средний |
| Полная страница истории | История хранится и ищется через палитру; `masaki://history` и отдельной страницы с группировкой/фильтрами нет | Средний |
| Разрешения и данные конкретного сайта в одной панели | Есть общий список решений, очистка данных и замок в адресе. Полного аналога информации Chrome о сайте, устройствах и выбранных настройках нет | Средний |
| Восстановление прерванной загрузки с прежнего места | После перезапуска progressing становится interrupted, объекта DownloadItem уже нет. «Скачать снова» начинает новую загрузку (`main/downloads.ts`) | Средний |
| Защита загрузок и опасных сайтов уровня Chrome | Собственная интеграция Google Safe Browsing/Enhanced Protection, репутационные проверки загрузок и UI предупреждений не найдены. TLS-проверка Chromium при этом не отключена | Высокий перед широким распространением |
| Полная совместимость расширений | Библиотеки дают tabs/action/contextMenus и магазин, но `declarativeNetRequest`, `chrome.webRequest`, nativeMessaging и управление хоткеями расширений ограничены; обходить ограничения обещанием «все расширения Chrome» нельзя | Средний |
| Защищённое видео | Нет поставки/настройки Widevine CDM. Обычные HTML5-аудио/видео и DRM-видео — разные возможности | Средний |
| Chrome Sync / Google Password Manager | У Masaki свой Google Drive appData-сейф; это не подключение к хранилищу Chrome. Есть отдельный импорт CSV, автоматическое чтение чужих паролей/кук не реализовано | Архитектурная граница |
| Обновления на macOS | Уведомление о версии есть, автоматическая установка выключена для неподписанной сборки (`updater.ts`); macOS на этом Windows-компьютере не проверялась | Средний |

Ближайший практический порядок: демонстрация экрана и HTTP/прокси-вход → корректная работа
менеджера в разрешённых iframe → Signal API и подтверждение владельца сейфа → выбор устройств →
папки закладок, история, перевод и PWA. Это список дальнейших работ, а не уже реализованные функции.

## Проверки и их границы

Временные профили, скрытые окна, выдуманные аккаунты; данные установленного браузера не меняются.

- `npm run typecheck` и `npm run build`.
- `node scripts/browser-compat-test.mjs`: повторный focus после заполнения, первый клик входа,
  выбор клавиатурой и смена аккаунта; Google в панели и popup; прикладные ссылки и редиректы,
  отмена и уход со страницы; перенос текста/файла/картинки со страницы, лимит размера,
  отдельный жест перестановки; неизменность поверхности во всех кадрах раскрытия панели.
- `node scripts/passkeys-test.mjs --local-only`: создание ES256/RS256, проверка ключей и подписей
  как сервером, вход через окно и conditional-список, поздний запрос после фокуса, отмена,
  excludeCredentials и отклонение чужого RP ID. Полная синхронизация двух профилей не входит в этот прогон.
- `node scripts/ai-image-test.mjs`: вставка/перенос, multipart POST с изображением в подставной Lens,
  переход в AI Mode и уменьшение большой картинки, отказ постороннему renderer.
- `node scripts/perf.mjs newtab`: скрытый замер двух раскрытий — в среднем 16,7 мс на кадр,
  без кадров длиннее 25 мс. При сворачивании были отдельные длинные кадры (до 116,6 мс);
  этот внеэкранный замер не является гарантией плавности обычного окна.
- Снимки `test-output/compat-*.png` и `pk-*.png` просматриваются отдельно после окончания анимаций.
- Собрана Windows x64-папка `dist/compat-fixes/win-unpacked`. Весь `browser-compat-test.mjs`
  повторно прошёл на её `Masaki.exe` (`MASAKI_COMPAT_EXE`), включая первый документ Google,
  подтверждение внешних ссылок и четыре варианта поверхности панели. Установленная копия не заменялась.

Передача внешнего URI проверяется с подставленной границей `shell.openExternal`: тест не запускает
Telegram и другие установленные программы. Для окончательной ручной проверки: открыть ссылку
`https://t.me/...`, нажать на странице переход в Telegram и подтвердить его в Masaki.
Подтверждение передачи в API Windows не доказывает регистрацию обработчика на конкретном ПК.

Перенос картинки перед отправкой показывает миниатюру. Только Enter/выбор поиска отправляет её
в Google Lens. Ограничение файла — 20 МБ; закрытые URL/неподдерживаемые изображения могут быть
отклонены с сообщением в интерфейсе. Файл пользователя не изменяется.
WebP отдельно проверен: NativeImage его не декодирует, поэтому Chromium превращает его в PNG для Lens.
