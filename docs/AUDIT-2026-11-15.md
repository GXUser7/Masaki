# Аудит Masaki и функции из списка сравнения с Chrome — 15 ноября 2026

Полный аудит проекта на поиск багов (в первую очередь — «сайты намертво зависают») и реализация
функций из таблицы «Чего не хватает относительно Chrome» в `docs/CHROME-COMPATIBILITY.md`.
Основа — `main` на момент `d40adc9` (0.7.6, локальные коммиты учтены), выпуски GitHub сверены.

## 1. Почему сайты намертво зависали — найдено и исправлено

### P0 — главные причины

| Причина | Что происходило | Исправление |
|---|---|---|
| Не обрабатывался `will-prevent-unload` | Сайт с beforeunload (Google Docs, редакторы, банки) молча отменял **любую** навигацию во вкладке: «Обновить», «Назад», адрес — ничего не делали, страница выглядела замороженной | `watchUnload` в main: синхронное окно «Покинуть страницу?» (событие живёт только до конца обработчика, поэтому асинхронная плашка невозможна — так же делает сам Chrome); окно Masaki поднимается, если свернуто; в скрытых тестах — автоответ «покинуть» |
| Исключение до `callback` в webRequest | Оба обработчика сессии (заголовки Google/YouCloud/SoundCloud и ответы блокировщика) без try/catch: любое исключение оставляло запрос висеть навсегда — сайт не грузился вовсе | Любой сбой отвечает неизменёнными заголовками/пустым продолжением |
| Потерянные ответы интерфейса | Окно страницы (`alert`/`confirm`) держит поток страницы через `sendSync`; если интерфейс перезагружался или падал — страница стояла замороженной навсегда. То же для разрешений, установки расширений, HTTP-входа, выбора экрана/устройств | `dropUiPending` при `did-finish-load`/`render-process-gone` интерфейса снимает все ждущие вопросы («отмена»/«остаться»/отказ) |

### P1/P2 — остальное из аудита

- **glass-page.js** (аддон «Прозрачные сайты»): сайты, пишущие в `<html>` служебные атрибуты каждый
  кадр, запускали бесконечные полные ресканы — страница занималась только ими. Теперь смену темы
  запускает белый список атрибутов (class, data-theme, color-scheme, …); `saved` чистится от
  вынутых из DOM элементов.
- **passkeys**: новый запрос не отменял старый (сайты с авторетраем получали серию отказов);
  ответ «Войти» без ключа молча игнорировался; conditional-запрос жил вечно; RSA-2048 создавался
  синхронно (заморозка main до секунды). Всё исправлено + окно ключа перечитывается при загрузке
  интерфейса (`passkeys.prompts`).
- **Таймауты там, где их не было**: `executeJavaScript` по фреймам при выгрузке вкладок (3 с),
  превью вкладок `capturePage` (3 с), значки сайтов и подсказки поиска, все запросы к Google в
  синхронизации, подключение к каналу Discord, скачивание значков (проверка `content-length` до
  чтения тела, отрицательный ответ не кэшируется навсегда).
- **Окно HTTP-входа** не плодится на авторетрае (дедуп по host+realm); окно установки расширения
  отвечает отказом через 3 минуты.
- **Ретранслятор yt-dlp**: сокет апстрима закрывается, если yt-dlp ушёл во время подключения
  (утечка сокетов).
- **Импорт CSV паролей** отдаёт поток главному процессу между партиями — вкладки не замерзают
  на тысячах записей; RSA в passkeys создаётся асинхронно.
- **Наглядность**: вкладка с открытым окном страницы (`alert` блокирует её поток) помечается
  точкой в панели и в доке — «зависший» сайт теперь объясним.

Узкий регресс — `node scripts/audit-fixes-test.mjs <режим>`, режимы: `unload`, `history`,
`display`, `iframe`, `autofill`, `passkey`.

## 2. Функции из списка сравнения — сделано

| Пункт списка | Что реализовано |
|---|---|
| Пароли и passkey во встроенных iframe | `guest.js` — сессионный preload + `nodeIntegrationInSubFrames`; список аккаунтов, сохранение и заполнение пароля, запросы WebAuthn работают во фреймах (origin — самого фрейма); служебные события интерфейса остались только главному фрейму |
| Согласование ключей после удаления на сайте (Signal API) | `PublicKeyCredential.signalUnknownCredential / signalAllAcceptedCredentials / signalCurrentUserDetails` → сейф Masaki сверяется с сайтом (удаление, список действующих, имя пользователя) |
| Тихое создание passkey | Не поддерживается намеренно; страницы получают внятный `NotSupportedError`, согласованный с `getClientCapabilities` (был «пользователь отказал») |
| PRF / largeBlob | Вывод ключей шифрования сайтов (HMAC-SHA-256, секрет у записи, зашифрован safeStorage, едет в сейф); largeBlob — чтение/запись блоба до 1 МБ вместе со входом |
| Повторная проверка владельца сейфа | PIN ключей доступа: задаётся/снимается в менеджере паролей, хранится только в профиле (PBKDF2-SHA-256, 150 000), окно подтверждения спрашивает PIN, неверный — ошибка в окне |
| Генерация и проверка паролей | Генератор (16 знаков, без похожих 0O1lI) у поля пароля; «Проверка паролей»: слабые (короткие/без цифр), повторённые на разных сайтах, не менявшиеся больше года; экспорт CSV открытым текстом (файл выбирает пользователь) |
| Автозаполнение адресов, телефонов, карт | `main/autofill.ts`: адреса и карты, список у полей форм по `autocomplete` (name/tel/postal-code/cc-number/…), выбор заполняет всю форму; номер карты — safeStorage, на странице только по выбору; проверка Луна; разделы в менеджере паролей; синхронизация в общем шифрованном сейфе |
| Демонстрация экрана | `setDisplayMediaRequestHandler` + стеклянный выборщик со снимками экранов и окон; звук системы (loopback) на Windows; отказ доходит до страницы (не «вечное ожидание») |
| WebUSB / WebHID / Web Serial / Web Bluetooth | Выборщики устройств в стиле окна ключа; права usb/hid/serial/bluetooth выдаются без лишнего вопроса — выбор устройства и есть подтверждение |
| HTTP/прокси-аутентификация | `app.on('login')` + окно логина Masaki (хост, realm, прокси) вместо молчаливого отказа |
| Папки закладок | Импорт из Chrome сохраняет папку; в панели избранного плитки группируются под сворачиваемым заголовком; в настройках у каждой закладки поле «Папка»; папка синхронизируется вместе с избранным |
| Полная страница истории | `masaki://history`: лента по дням, поиск, период, удаление записи и очистка; Ctrl+H и кнопка в панели открывают её; удаление отдельной записи — новое `history:remove` |
| Разрешения и данные сайта в одной панели | «Сведения о сайте»: щит в адресной капсуле — соединение, решения по разрешениям со сбросом, перевод, очистка кук и данных сайта; Esc закрывает |
| Регистрация сайтом обработчика протокола | `navigator.registerProtocolHandler('web+…')` записывается по origin фрейма; ссылки на схему открываются на сайте-обработчике (шаблон с %s), мимо системного вопроса «открыть приложение?»; управление в настройках |
| Установка сайтов как приложений (PWA) | «Установить как приложение…» в меню страницы: собственное окно без интерфейса Masaki с общими куками и входами (сессионные preload'ы работают — ключи доступа и пароли в приложении тоже); ярлык на рабочем столе; запуск `Masaki.exe --app=<адрес>` (второй запуск открывает окно в работающем Masaki); список в настройках |
| Перевод страницы | Пункт меню «Перевести на русский» переведён на живой формат `*.translate.goog` (прежний `translate.google.com/translate?u=` Google отключил) |

### Не реализовано (технически невозможно в Electron, без обхода чужих систем)

- **Widevine** — CDM нельзя поставлять с браузером (Netflix и т. п. останутся недоступны).
- **Chrome Sync / Google Password Manager** — ключи Chrome закрыты для сторонних браузеров;
  у Masaki своя синхронизация через Google Диск (адресация и пароли уже свои).
- **FedCM-окно** — окно выбора аккаунта рисует сам Chromium, у Electron его нет; вход через Google
  работает всплывающим окном (как в Firefox).
- **Вход по QR с телефона (hybrid)** — нужен собственный hybrid-провайдер и канал с телефоном;
  «Ключ безопасности…» по-прежнему отдаёт запрос системному WebAuthn (USB-ключи).
- **declarativeNetRequest для расширений** — ограничения Electron; у Masaki свой блокировщик.
- **Safe Browsing** — по решению пользователя пропущен.
- macOS-обновления — нужна подпись Apple (как и было).

- `npm run typecheck` и `npx electron-vite build` — чисто на каждом шаге; коммиты по мере
  проверки, пуша и релиза нет (по регламенту).

  изменений, стоит разобрать отдельно.
