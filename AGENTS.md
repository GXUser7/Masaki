# Masaki — памятка для агентов

Masaki — настольный браузер для Windows на Chromium (Electron 44), с собственным интерфейсом:
матовое стекло + Material 3 Expressive. Пишется для одного пользователя, общаемся по-русски.
Цель — функциональность обычного Chrome в своём дизайне. Раньше назывался **Frost** (папка проекта
пока так и называется); при первом запуске Masaki переносит профиль `%APPDATA%\Frost` → `%APPDATA%\Masaki`
(`migrateFromFrost` в main), а адреса `frost://` в сессии и истории — в `masaki://`.

## Быстрый старт

```bash
npm install
npm run dev          # разработка: интерфейс перезагружается на лету
npm run typecheck    # tsc без сборки
npm run smoke        # сборка + основной автотест, снимки окна в test-output/
npm run test:addons  # сборка + тест аддонов и меню Chrome (видео, QR, блокировщик, расширение)
npm run test:import  # сборка + тест переноса из Chrome на подставной папке Chrome
npm run test:sync    # сборка + синхронизация двух профилей через подставной Google (scripts/mock-google.mjs)
npm run test:passwords # сборка + менеджер паролей: CSV, автозаполнение, сохранение, шифрованная синхронизация
npm run test:passkeys  # сборка + ключи доступа: создание, вход (окно и автозаполнение), подписи, синхронизация
npm run test:youcloud  # сборка + YouCloud: мост, мини-плеер с обложкой, поиск из палитры (нужен дев-сервер YouCloud/web)
npm run perf         # замер плавности сворачивания панели (интервалы кадров)
npm run pack         # dist/win-unpacked/Masaki.exe — то, что запускает пользователь
npm run icon         # перерисовать build/icon.png
```

Окружение: Windows 10, Git Bash и PowerShell. В npm 11 включён `allow-scripts`, поэтому предупреждения
об install-скриптах (esbuild и т. п.) — норма, всё работает.

Профиль пользователя: `%APPDATA%\Masaki` — settings.json, session.json, history.json, favicons.json,
permissions.json, window.json, custom-wallpaper.*, adblock-engine.bin, sync.json (состояние синхронизации),
sync-auth.bin (ключ Google, токен входа и ключ паролей, зашифрованы safeStorage — на другом компьютере
не расшифруются), passwords.json (пароли, каждый зашифрован safeStorage; логины и сайты — открыто, как у Chrome),
passkeys.json (ключи доступа: закрытый ключ PKCS#8 зашифрован safeStorage, сайт и имя — открыто). Вкладки живут в сессии
`persist:frost` — имя осталось от старого названия, в ней куки и входы пользователя: **не переименовывать**.

### Как устроены вкладки

- Каждая вкладка — `<webview>` (не WebContentsView): только так стеклянная капсула, палитра и меню
  лежат поверх страницы и размывают её через `backdrop-filter`.
- Неактивные webview скрыты `visibility: hidden` и продолжают жить. Порядок в DOM — по порядку
  создания (`t1`, `t2`…), а не вкладок: перестановка узла webview перезагрузила бы страницу.
- Внутренние страницы `masaki://newtab`, `masaki://settings`, `masaki://addons`, `masaki://passwords` —
  React-компоненты, а не webview (`Tab.kind`, таблица `internalPages` в store).
- Методы webview можно звать только после `dom-ready`: `wv(id)` из store возвращает элемент лишь
  когда он готов.

### Синхронизация (src/main/sync.ts)

- **Chrome Sync закрыт** для сторонних браузеров с 15.03.2021 (ключи Chrome выдаются только Chrome).
  Брать ключи из Chrome — выдавать себя за Chrome, так не делаем. У Masaki своя синхронизация через
  **Google Диск, папку приложения** (`appDataFolder`, доступ `drive.appdata` — остальные файлы Диска не видны).
- Ключ OAuth (тип «Desktop app») пользователь создаёт сам в своём проекте Google Cloud (инструкция — в
  разделе «Синхронизация» настроек). Приложение в Google Cloud должно быть **опубликовано** (Audience →
  Publish app), иначе refresh-токен живёт 7 дней. **Проверку приложения (Verification) проходить не нужно**:
  drive.appdata неконфиденциальный, логотип не загружать (с ним Google требует проверку бренда); экран
  «Приложение не проверено», если он появится, проходится через «Дополнительные настройки» (это есть в гайде). Вход: страница Google во вкладке Masaki (или системный
  браузер) → код возвращается на `http://127.0.0.1:<порт>` (PKCE) → вкладка закрывается.
- Файлы на Диске — простой JSON, чтобы подключилась и будущая Android-версия:
  `prefs.json` (поля настроек `{t, v}`, кто позже изменил — тот прав), `history.json` (объединение,
  `clearedAt` — очистка), `device-<id>.json` (открытые вкладки устройства). Что синхронизируется —
  таблица `FIELDS`; **новую настройку решать отдельно** (своё у устройства — не добавлять туда).
- Первый вход: избранное и ярлыки **объединяются**, настройки берутся из аккаунта.
- Настройки и история, пришедшие с Диска, главный процесс шлёт событиями `settings-changed` /
  `history-changed`; интерфейс кладёт их в состояние **без** отправки обратно.
- Тесты — только с подставным Google: `MASAKI_SYNC_MOCK=<адрес>` перенаправляет вход, токены и Диск.

### Пароли (src/main/passwords.ts, src/preload/guest.ts)

- Google Password Manager закрыт для сторонних программ, пароли Chrome — тем более (их шифрование —
  защита от чужих программ, **не трогать**). Перенос — только экспорт CSV пользователем
  (passwords.google.com → Настройки → Экспорт): Masaki замечает скачанный `*Passwords*.csv`, предлагает
  перенести и **удаляет файл**. Понимает форматы Google/Chrome, Firefox, Bitwarden; android:// пропускает.
- Пароль в интерфейс уходит только по «показать»; в страницу — из главного процесса после выбора
  аккаунта, и только если **фрейм** вкладки (`senderFrame.origin` / `mainFrame.origin`) того же сайта.
  Словам страницы о своём адресе не верим. Скрипт работает только в главном фрейме вкладки.
- Список аккаунтов у поля рисует интерфейс поверх webview (`ipc-message` `pw:show` / `pw:hide` через
  `sendToHost`); выбор — по `mousedown`, иначе страница успевает спрятать список.
- Предложение сохранить — после отправки формы (submit, клик по кнопке, Enter). Вход в два шага: логин
  с первой страницы запоминается для вкладки (`pw:username`). «Никогда для сайта» — список `never`.
- Синхронизация паролей — `vault.json` на Диске: каждая запись AES-256-GCM (AAD — id записи), ключ —
  PBKDF2-SHA256 (600 000) из фразы пользователя. Фразу **восстановить нельзя**; «Забыли ключ?» удаляет
  пароли с Диска (на компьютерах они остаются). Удаление — пометка `deleted`, чтобы дошло до других устройств.
- Перед показом пароля нет проверки Windows Hello: на ПК пользователя его нет (`DeviceNotPresent`).
- Тесты — только выдуманные пароли; `MASAKI_DOWNLOADS` уводит загрузки теста из папки пользователя.

### Ключи доступа (src/main/passkeys.ts, src/preload/passkey-page.ts)

- Встроенный WebAuthn Electron ходит в Windows, а у пользователя нет Windows Hello — поэтому у Masaki
  **свой аутентификатор платформы**. Скрипт вкладки (`executeInMainWorld`) подменяет
  `CredentialsContainer.prototype.create/get` для `publicKey`, говорит сайтам «платформа умеет»
  (`isUserVerifyingPlatformAuthenticatorAvailable`, `isConditionalMediationAvailable`, `getClientCapabilities`)
  и отдаёт запрос через мост в главный процесс (`pk:create|get|abort`). Ответ собирается в объекты
  с прототипами `PublicKeyCredential` / `Authenticator*Response` (есть `toJSON`, `getTransports`, `getPublicKey`).
- Главный процесс: origin — по фрейму вкладки (только главный фрейм; https или http://localhost), RP ID —
  хост или его родитель, но не публичный суффикс (`tldts`, с частными доменами вроде github.io).
  `clientDataJSON` собирает он сам. Ключи ES256 (по умолчанию), EdDSA, RS256; attestation `none`, AAGUID
  Masaki, счётчик 0, флаги UP+UV+BE (+BS, если включён сейф на Диске).
- Подтверждение — только в интерфейсе Masaki: окно поверх вкладки (`PasskeySheet`, видно для активной
  вкладки) или строка ключа в списке автозаполнения у поля `autocomplete="… webauthn"` (mediation
  conditional). UV ставим после этого подтверждения: Windows Hello нет, ключ привязан к учётной записи
  Windows (DPAPI) — как разблокированный сейф у Bitwarden/KeePassXC. Свой PIN — возможное улучшение.
- «Ключ безопасности…» в окне и `authenticatorAttachment: 'cross-platform'` отдают запрос встроенному
  WebAuthn как есть (USB-ключи). В тестах эту кнопку не нажимать — откроется системное окно Windows.
- Синхронизация — тот же `vault.json`, записи с `kind: 'passkey'` (закрытый ключ PKCS#8 base64url).
- Тест — `scripts/passkeys-test.mjs` на http://localhost: подписи и форматы проверяет сам тест, как сервер.

### YouCloud (src/main/youcloud.ts, preload/guest.ts, lib/youcloud.ts)

- YouCloud — музыкальный сайт пользователя (репозиторий YouCloud, папка `web/`, живой адрес
  https://youcloud.inkerror67.workers.dev, дев-сервер http://localhost:5190). В Chrome ему нужно
  расширение (`web/extension`), которое ходит в Яндекс и YouTube с IP пользователя. **В Electron это
  расширение не работает** (нет `declarativeNetRequest` и `cookies`), поэтому Masaki сам говорит с сайтом
  его протоколом: `guest.ts` — половина «страницы» (сообщения window `{yc: 'page'|'ext'}`, hello с
  `host: 'masaki'`), `main/youcloud.ts` — половина «фона». Расширение YouCloud Masaki не загружает
  (`isYouCloudExtension`): вдвоём они отвечали бы сайту дважды.
- Мост отвечает только главному фрейму вкладки YouCloud (по `senderFrame.origin`) и ходит только к хостам
  Яндекса и YouTube. Заголовки, которые fetch не даёт (Origin, Referer, Cookie), ставит единственный
  `onBeforeSendHeaders` сессии по метке `ycr=<id>` в адресе — как правила DNR у расширения. Вход в YouTube —
  куки сессии вкладок и SAPISIDHASH, на страницу они не попадают.
- Входы: `sc-login`/`ya-login`/`yt-login` открывают вкладку Masaki; токен SoundCloud ловится по cookie
  `oauth_token`, Яндекса — по `#access_token` в адресе music.yandex.ru, вход Google — по cookie SAPISID.
  Вкладка входа закрывается командой `close-wc`, Masaki возвращается во вкладку YouCloud.
- В Masaki сайт без своего фона: preload ставит `data-host="masaki"` до первой отрисовки, карточка
  страницы — стекло «как у панели», тему (цвет `--primary` и светлоту) интерфейс шлёт сайту (`yc:theme`).
  Аддон «Прозрачные сайты» YouCloud не трогает.
- Мини-плеер — для любого сайта с Media Session: `media-page.ts` в мире страницы перехватывает
  metadata/playbackState/setPositionState/setActionHandler и шлёт JSON (`sendToHost('media')`);
  кнопки зовут обработчики сайта (`webview.send('media:action')`). Данные страницы проверяет `parseMedia`.
  Цвет плеера — из обложки (`media:art` → data:, `useArtColors`).
- **Звук YouTube — через yt-dlp** (`main/ytdlp.ts`, сообщение `yt-stream`, мост версии 0.7), как в
  Android-приложении YouCloud: в браузере YouTube многим трекам отказывает (клиентам сайта — «подтвердите,
  что вы не бот», без PO-токена поток обрывается на 1 МБ), а yt-dlp их достаёт. yt-dlp.exe — ночная сборка
  с GitHub, сверка с SHA2-256SUMS, проверка обновления раз в сутки и после сбоя; лежит в профиле
  (`yt-dlp/`). JS-задачи YouTube решает Masaki сам: `--js-runtimes node:<exe>` + `ELECTRON_RUN_AS_NODE=1`.
  Сначала без входа, при отказе — с куками youtube.com во временном файле (удаляется после запуска);
  прокси — как у сессии вкладок (`resolveProxy`), иначе ссылка googlevideo привязана к другому IP.
  Скачивается заранее, когда сайт говорит hello. Если yt-dlp не смог — сайт пробует своих клиентов.
- Палитра: команда «YouCloud», пауза/следующий/предыдущий трек, строка «Найти в YouCloud» (если YouCloud
  открывали) → `#/search/<запрос>`.

## Решения, утверждённые пользователем (не менять без просьбы)

Редизайн 2026-10-10 (холст «Masaki — редизайн интерфейса» на claude.ai: пользователь выбрал
кнопки окна A, панель A, док A и все 12 идей, попросив сохранить матовое стекло и M3 Expressive):

- Нет верхней панели. Развёрнуто: «тихая» боковая панель слева — шапка (логотип, кнопка панели,
  **кнопки окна**), адресная капсула («назад/вперёд» внутри неё и только когда есть куда, звёздочка
  при наведении), избранное, «Вкладки · N» с кнопкой «+», вкладки с группами, мини-плеер, низ:
  аккаунт (аватар + статус синхронизации) / загрузки / история / меню. Настройки и аддоны — в меню.
- Свёрнуто (Ctrl+B): внизу **док, вариант A «Три острова»** (выбран пользователем 2026-10-11 на холсте
  «Masaki — варианты дока»): слева остров вкладок, по центру **капсула** (панель, адрес со значком сайта,
  меню, кнопки окна), справа мини-плеер. Всё видно сразу, над страницей при наведении ничего не
  выпрыгивает (прежние «вкладки над капсулой» пользователь счёл пустой тратой места). Капсула всегда
  по центру (сетка 1fr · auto · 1fr). Вкладки: просторно — с названиями, тесно — значками, совсем
  тесно — значки вокруг активной и «+N» со списком всех вкладок и поиском (`popover: 'tabs'`); колесо над
  островом сдвигает видимое окно. Плеер в тесноте теряет название, потом «предыдущий» (container query).
  Пока страницу листают вниз, док худеет целиком (значки 22 px, домен, обложка с кольцом прогресса),
  а страница становится выше (иначе сжатие бессмысленно — замечание пользователя); наведи — вернётся.
  Страница заканчивается над доком.
- **Кнопок окна поверх сайта нет** (пилюля в углу закрывала аватары и уведомления сайтов). Двойной
  щелчок по шапке или пустому месту капсулы — развернуть; тянуть — двигать. Задержка курсора на
  «развернуть» — свои раскладки окна (½, ⅔+⅓, ⅓×3, ¼×4): Snap Layouts Windows у самодельных кнопок
  не показывает.
- Обои (своя картинка или обои Windows) — **размытый фон всего окна** одной силы (¾ от настройки
  «Стекло»): под панелью и под прозрачной новой вкладкой одно полотно (просьба пользователя). Панель
  второй раз не размывает (`.wallbg`), картинка должна угадываться, а не быть пятном. При развороте окна рамка вокруг страницы 6 px. Шкала скруглений `--r-xl/l/m/s` (28/24/16/12),
  интерактивное — пилюли, которые на наведении и нажатии морфят радиус (язык M3 Expressive).
- Загрузка: за значком вкладки перетекает фигура M3 (индикатор M3 Expressive, кадры `m3morph`
  генерирует `MorphKeyframes`), а сама загрузка **заливает адресную капсулу** слева направо (`LoadFill` в
  `Extras.tsx`: рывок до ~20 %, ползёт к ~85 %, по готовности доезжает и гаснет; едет transform, не width).
  Волнистую линию по верхней кромке страницы убрали по просьбе пользователя 2026-10-11 — на сайте она смотрелась чужой.
- Подсказки клавиш в постоянном интерфейсе не показываем — только во всплывающих подсказках и в палитре.
- Палитра (адрес + поиск + AI Mode) всегда по центру страницы, поле-источник на это время прячется
  (не должно быть двух полей поиска на экране). Клик по строке поиска — результат в текущей вкладке,
  хоткей — в новой (кроме пустой новой вкладки).
- «AI Mode» — это AI Mode поиска Google (`google.com/search?udm=50&q=`), не Gemini-панель.
  Кнопка AI Mode — действие «спросить»: открывает палитру в режиме AI; закрыли палитру — режим
  вернулся к настройке «AI Mode при запуске».
- Новая вкладка: часы в стиле экрана блокировки Pixel (8 стилей), поиск, ярлыки. Печать на новой
  вкладке сразу открывает палитру.
- Плитки избранного и ярлыков: форма M3 (меняется правым кликом, плавно перетекает), цвет — из
  значка сайта; в панели цвет приглушён и «оживает» при наведении. Серые обои → монохромная тема.
  Цвет можно выбрать в том же меню (ряд кружков: «Авто», 10 оттенков по кругу тона HCT, «Свой…»;
  `Shortcut.color` = '#rrggbb', нет поля — «Авто»); тона плитки считаются из него так же, как из значка
  (`tileColorsFor` в `lib/iconColor.ts`). Светлые значки на прозрачном (белый глиф, SVG с
  `prefers-color-scheme`) стоят на тёмной подложке `--plate`, иначе белое на белом; решает `scanIcon`,
  при смене темы значки разбираются заново. Битая картинка → буква, не пустой кружок.
- Новая вкладка с картинкой фона — как экран блокировки Pixel: часы, дата и подписи светлые с тенью
  в обеих темах, поле поиска на тёмном стекле.
- Часы — по скриншотам Pixel (Android 16), которые прислал пользователь: «Стандартные» (тонкие,
  один светлый тон), «Мозаика» (свой блочный шрифт 3×5 в `Clock.tsx`, тона полосами), «Цифры»
  (крупные 12/3/6/9 и стрелки), «Антиква» (узкая Fraunces), «Наложение» (жирные внахлёст, шахматные
  тона), «Пузыри» (разноцветные с обводкой), «Каллиграфия» (Fraunces SOFT/WONK). **«Аналоговые» и
  «Сводку» не менять** — пользователя они устраивают. Цвета — палитра `--k-ink/acc/acc2/3/deep`.
- Удобства (идеи из редизайна, `components/Extras.tsx`): «взгляд» — Alt+клик по ссылке открывает её
  карточкой поверх страницы; две вкладки рядом (меню вкладки «Открыть рядом», ползунок между);
  превью вкладки при наведении (снимок делает главный процесс, `tab:capture`); мини-плеер звука
  фоновой вкладки; кольцо загрузки и перетаскивание скачанного файла из списка; архив неактивных
  вкладок (настройка, по умолчанию выключен); группы вкладок; жест «назад/вперёд» свайпом по
  тачпаду; команды в палитре через «>»; поиск по вкладкам **Ctrl+Shift+A** (как в Chrome; у аддонов
  хоткея больше нет — команда «>аддоны» или меню).
- По умолчанию: тёмная тема, палитра «Мята», сильное стекло.

## Проверка изменений

1. `npm run typecheck`, затем `npm run smoke` (и `npm run test:addons`, если трогали меню, аддоны,
   медиа). Снимки — в `test-output/*.png`, **смотреть их глазами**, а не только код возврата.
2. Долгие команды — всегда под `timeout` (например `timeout 560 node scripts/smoke.mjs`).
3. Сайты Google (поиск, AI Mode, вход) **не открывать из Playwright**: у автоматизации свой отпечаток,
   и Google отдаёт капчу на IP пользователя. Для них — самопроверка без автоматизации:
   ```bash
   MASAKI_PROFILE=<временная папка> MASAKI_SELFTEST_URL=<адрес> MASAKI_SELFTEST_SHOT=<png> \
   MASAKI_SELFTEST_WAIT=8000 MASAKI_SELFTEST_EVAL="<выражение во вкладке>" npx electron .
   ```
   И даже так не долбить Google часто.
4. Тесты всегда запускаются с `MASAKI_PROFILE` во временной папке — профиль пользователя не трогать.
   И с `MASAKI_TEST_INACTIVE=1`: окно открывается без фокуса, иначе то, что пользователь печатает
   в это время, уходит в тестовое окно (так уже было).
   Если нужен его профиль для отладки — копировать во временную папку и печатать только устройство
   данных, без почты, имён и cookie; копию удалить.

## Подводные камни (уже наступали)

- **Наведение поверх страницы в тестах не держится**: `useHoverOverPage` сверяется с настоящим
  курсором Windows, а Playwright двигает мышь понарошку. Поэтому в доке нет ничего, что видно только
  при наведении, а сжатый док тесты проверяют снимком.
- **Playwright подменяет `prefers-color-scheme` на светлую** (по умолчанию у `electron.launch`) — в смоуке
  стоит `colorScheme: null`, иначе SVG-значки с медиазапросом рисуются не так, как у пользователя.
- **Боковые кнопки мыши** до `app-command` не доходят: Chromium сам разбирает WM_XBUTTON* и отдаёт их
  странице как mouseup с button 3/4. Их ловит `preload/guest.ts` (после обхода события: страница могла
  отменить — тогда кнопка её, как в Chrome) и интерфейс (`App.tsx`), шлют `nav:mouse` в main, тот ведёт
  назад/вперёд именно ту вкладку, где нажали, и гасит дубль от `app-command`. Тест — настоящий
  PostMessage(WM_XBUTTON*) в окно (шаг `mouseNav`), не SendInput: тот двигал бы мышь пользователя.
- **Ctrl+колесо** Electron сам не применяет — только шлёт `zoom-changed`; main передаёт его интерфейсу
  командой `zoom` с `wcId` вкладки, масштаб запоминается в `tab.zoom`, как у Ctrl+=.
- **Переход без действия пользователя** (`location.href = …` из скрипта) Chromium не пускает в историю
  «назад» — в тестах переходить настоящим кликом по ссылке.
- **Синтетические нажатия Playwright не проходят через `before-input-event`** главного процесса.
  Поэтому у хоткеев есть запасной обработчик в интерфейсе (`shared/shortcuts.ts` используется в обоих
  местах). Настоящая клавиатура идёт через main.
- **Координаты `context-menu` у webview приходят в системе окна**, не страницы. Для
  `inspectElement`, `copyImageAt`, медиа-действий вычитаем положение webview и делим на zoom.
- **`position: fixed` внутри элемента с `transform`** считается от этого элемента. Подсказки дока и
  прочие плавающие элементы рендерить вне трансформированных контейнеров.
- **Совпадение имён CSS-классов** уже дважды ломало вёрстку (`.row` у часов и палитры, `.ntp` у дока
  и новой вкладки). Новым классам давать уникальные префиксы.
- `button { font: inherit }` должно быть с нулевой специфичностью, иначе сбрасывает `line-height`
  у кнопок вроде часов.
- Наведение над элементами поверх webview залипает (страница «съедает» уход мыши) — для капсулы
  наведение проверяется по реальному курсору из main (`masaki.cursor()`, хук `useHoverOverPage`).
- `overflow: clip` у `html/body/.app` — чтобы фокус и `scrollIntoView` не могли программно сдвинуть
  интерфейс.
- **Анимации размеров ломают плавность**: webview пересчитывает вёрстку на каждом кадре. Сворачивание
  панели сделано через FLIP (страница встаёт сразу, сдвиг дорисовывает видеокарта) — так и держать;
  проверять `npm run perf`.
- Electron 44: буфер обмена асинхронный, картинка — `clipboard.write([new ClipboardItem(...)])`,
  `writeImage` нет. Расширения — `session.extensions.loadExtension`.
- **Вход в Google**: на `accounts.google.com` Masaki представляется Firefox ESR (заголовки в
  `onBeforeSendHeaders` + `navigator` через `preload/guest.ts`), иначе «браузер небезопасен».
  Остальные сайты видят обычный Chrome. Список аккаунтов — POST на `ListAccounts` с
  `Origin: https://www.google.com`.
- `onBeforeSendHeaders` у сессии может быть только один — его занимает вход в Google. Блокировщик
  (Ghostery) использует onBeforeRequest/onHeadersReceived; его включение сериализовано очередью.
- `@ghostery/adblocker-electron` — **единственная runtime-зависимость** (в `dependencies`): он ищет свой
  preload через node_modules, вшивать его в бандл нельзя. Всё остальное — devDependencies, Vite
  собирает это в бандл.
- Серые обои: библиотека цветов без запасного цвета подставляет синий Google — для них монохромная
  схема (`paletteFromImage`).
- **Прозрачные сайты**: фон у `html` сайты задают и через `!important` (YouTube) — снимаем инлайн-стилем
  с `important`, он сильнее любых правил. Прозрачным делаем только залитое цветом фона сайта; всплывающие
  окна (`role=dialog`, фиксированные блоки не у края) не трогаем — иначе их текст ляжет на страницу.
  `backdrop-filter` внутри вкладки не использовать: он размывает не то, что видно, полоса выходит
  светлее страницы. Проверка — шаг «сайт-приложение» в `test:addons` (`scripts/fixtures/app-like.html`).
  Прозрачность по умолчанию **«Как у панели»** (`addons.glass.match`): под сайтом то же стекло, что у
  боковой панели (`--wall` 50/44 %, зерно, обводка, без второго размытия обоев), шапки сайта — цветом
  панели. Светлый сайт в тёмной теме (и наоборот) остаётся на своём цвете с ползунком, иначе пропадёт
  текст. «Своя» — прежний ползунок. Управление аддонами — только на странице «Аддоны», не кнопками в
  шапке панели или капсуле (пользователь такое отверг).
- **Перенос из Chrome** — только открытые данные: закладки (`Bookmarks`, JSON), ярлыки новой вкладки
  (`Preferences` → `custom_links`), история (`History`, SQLite — читаем копию, Chrome держит файл
  открытым; время — микросекунды от 1601 года, переводим прямо в SQL, иначе не влезает в number).
  **Пароли и куки Chrome не трогать** (их шифрование — защита от чужих программ, обходить его — то, чем
  занимаются стилеры); пользователь входит на сайты сам. Тесты — только с `MASAKI_CHROME_DIR`, настоящий
  Chrome пользователя проверять только количествами, без адресов и названий.
- `data:`-страницы — небезопасный контекст: геолокация и т. п. там не работают, для тестов разрешений
  брать `file://`.

## Стиль кода

- Комментарии и тексты интерфейса — по-русски, объясняют «почему», а не «что».
- TypeScript strict, React-компоненты-функции, состояние — zustand (`useStore`), DOM-доступ к webview —
  через реестр в store.
- Цвета — только CSS-переменные (`--primary`, `--pc`, `--tc`, `--glass`, `--glass-pop` …), никаких
  захардкоженных цветов в компонентах (исключение — красная кнопка закрытия окна).
- Пружины M3 Expressive: `var(--spring)` и `var(--snap)`; формы — из `lib/shapes.ts`.
- Иконки — пути Material Symbols в `components/Icon.tsx`.
- Правки больших файлов делались Python-патчами с точными заменами; это нормально, но после правок
  всегда `typecheck`.

## Сборка и выдача пользователю

- Пользователь запускает `dist/win-unpacked/Masaki.exe` — через ярлыки «Masaki» на рабочем столе и в меню
  «Пуск» (указывают на этот путь; при переименовании папки проекта их нужно перенаправить). Запуск проекта
  кнопкой в Claude стартует с отдельным чистым профилем — пустое окно там не значит, что данные пропали.
  Если Masaki у него открыт, папку не перезаписать:
  собирать в `dist/next` (`npx electron-builder --win dir -c.directories.output=dist/next`) и подменять
  `dist/win-unpacked` после закрытия Masaki (можно фоновой задачей, ждущей закрытия процесса).
- Перед выдачей: typecheck, smoke (и test:addons при необходимости), посмотреть снимки, собрать.
- Релиз на GitHub (github.com/GXUser7/Masaki): поднять `version` в package.json, собрать установщик
  в отдельную папку — `npx electron-vite build && npx electron-builder --win nsis -c.directories.output=dist/release`
  (обычный `npm run dist` пересобирает dist/win-unpacked, которым пользуется пользователь), затем
  `gh release create v<версия> dist/release/Masaki-Setup-<версия>.exe` с SHA-256 в описании.
  Установщик не подписан — SmartScreen предупреждает, это описано в README. Снимки для README — `npm run screens`.
- Код — на GitHub (публичный репозиторий). Коммитить и пушить только по просьбе пользователя.

## macOS (экспериментально)

- Собирается в GitHub Actions (`.github/workflows/macos.yml`, macos-14): `npm ci`, typecheck,
  `electron-builder --mac dmg zip --arm64 --x64`, артефакт **Masaki-mac**. Подписи Apple нет — ad hoc
  (`mac.identity: "-"`, hardenedRuntime выключен), иначе на Apple Silicon не запустится. Локально — `npm run dist:mac`.
- Отличия в коде — только по `process.platform === 'darwin'` (на Windows ничего не меняется): окно с
  `titleBarStyle: 'hidden'` и «светофорами» в шапке панели (`trafficLightPosition`, место под них —
  `.mac .side-top`; при свёрнутой панели прячутся `setWindowButtonVisibility`, кнопки окна — наши в
  капсуле); меню приложения из ролей appMenu/editMenu/windowMenu (без меню «Правка» на Mac не работают
  Cmd+C/V в полях; меню «Файл» нет — его Cmd+W закрыл бы окно); хоткеи уже принимают ⌘ как Ctrl
  (`shortcuts.ts`); «Обои Windows» спрятаны; Chrome для переноса — `~/Library/Application Support/Google/Chrome`;
  yt-dlp — `yt-dlp_macos`.
- **Проверить мак-версию здесь нечем** (разработка на Windows): что не так, сообщает друг пользователя с Mac.

## Чего пока нет

- Кнопок и всплывающих окон расширений Chrome (работают только расширения, меняющие страницы),
  установки из Chrome Web Store.
- У ключей доступа: входа по QR с телефона (hybrid), ключей в iframe (там встроенный WebAuthn), «тихого»
  создания ключа после входа паролем (`mediation: 'conditional'` у create), своего PIN перед входом.
- Автозаполнения в iframe и выбора аккаунта стрелками с клавиатуры; экспорта паролей.
- Android-версии (план: отдельное приложение на Kotlin + Compose + GeckoView, та же синхронизация).
- Защищённого видео (Widevine: Netflix и т. п.).
- Отдельной страницы истории и загрузок (история — в палитре, загрузки — во всплывающем окне).
- Папок избранного: закладки Chrome при переносе раскладываются в один плоский список.
- Установщика с автообновлением (`npm run dist` собирает NSIS, но обновлений нет).
- Кнопок плеера на панели задач Windows (thumbar) и своей реакции на медиаклавиши — их обслуживает Chromium.
- Дизайн-макеты — в артефакте-холсте «Masaki — варианты дизайна» на claude.ai (5 артбордов).
